# Architecture Decision Record (ADR-001)

## Title
**ADR-001: Multi-Format Tally Transport (XML, JSON, JSONEx), Electron Desktop Architecture, and Secure Preload IPC**

## Status
**ACCEPTED**

## Context
CFO Yantra requires a reliable, read-only enterprise integration desktop bridge for TallyPrime that displays live connection status, format capabilities, active company discovery, and actionable diagnostics on Windows desktop without compromising accounting data integrity or security.

## Decisions

### 1. Transport Priority & Fallback Strategy
- **Priority**: `JSONEx` $\rightarrow$ `JSON` $\rightarrow$ `XML`.
- **Automatic Fallback**: If JSON/JSONEx is unsupported by the target Tally installation, the bridge immediately falls back to XML without disrupting sync or crashing the desktop UI.

### 2. Electron + React UI with Secure Preload IPC
- **Decision**: Electron Main process acts as the supervisor for the Node.js bridge core. React Renderer interacts with the engine exclusively through `preload.js` with `contextIsolation: true` and `nodeIntegration: false`.
- **Security**: The renderer is prohibited from making direct network calls to Tally (`127.0.0.1:9000`). All requests are routed through verified IPC channels.

### 3. Read-Only Policy Gate & Exact Precision Math
- Outbound requests pass through `assertReadOnlyXml()`. Mutation attempts throw `READ_ONLY_VIOLATION`.
- Financial computations use `decimal.js` exact representations (banning floating-point arithmetic).

### 4. Cloud Persistence
- Cloud persistence remains exclusively on MongoDB Atlas (outbound HTTPS). SQLite, PostgreSQL, and other local DBs are omitted in favor of encrypted local spool files.
